0Bounding box

Minimum left and top, maximum right and bottom. The only real decisions are what an empty selection returns and whether the result is a Rect (no id) rather than a Box — say both, they cost nothing.

Note it spans to x + w, not x. A bounding box computed from origins alone is right whenever every object is the same size, which is exactly what your first hand-written test will look like.

null for an empty selection, not a zero rect. A zero rect at the origin is a real rectangle a caller will happily draw; null forces the caller to decide, and the type says so.

1Align translates; it never resizes

Align to what? The selection's own bounding box — that is what every design tool does, and the reason is worth one sentence: aligning to the canvas would move a selection the user did not ask to move.

The right-edge case is where implementations differ. left is x = bb.x, which is easy; right is x = bb.x + bb.w − b.w, and writing x = bb.x + bb.w puts every object just outside the box. Same shape for bottom. If you only test with equal-sized boxes both look identical — so make the boxes different sizes in your very first fixture.

2Distribute equalises gaps, not centres

These two are the same thing whenever the objects are the same size, and visibly different the moment they are not. Equal centres is a real feature that some tools also offer, but it is not what "distribute" means, and it looks wrong: with mixed widths the space between things visibly varies.

What is held fixed is the other half of the question. The two outermost objects do not move; everything between them is spread into the space they leave. Any other choice — centring the whole run, or anchoring to the canvas — moves objects the user positioned deliberately, and the first thing they will do is undo it.

5Say it out loud

"Align to the selection's own bounding box, not the canvas — otherwise I'd be moving the whole selection somewhere the user didn't ask for."
"Align translates. Widths and heights are never touched, and the right and bottom edges are bb edge minus the object's own size, which is the bit that's easy to get wrong with equal-sized test boxes."
"Distribute holds the two outermost objects still and equalises the gaps. Equalising centres is a different feature and it looks wrong when the objects differ in size — I'll make my fixture have three different widths so the difference is visible."
"Fewer than three objects: nothing to distribute, so I return them unchanged rather than erroring. And none of the three mutate — they return new boxes, because a selection tool shouldn't be able to corrupt the document by being asked a question."

The follow-up that arrives if you finish: what if the objects overlap? The gap arithmetic goes negative and the layout still works — objects overlap evenly, which is the correct generalisation. Say it rather than special-casing it; a clamp to zero would silently widen the selection's bounding box, which is the one thing distribute must not do.
