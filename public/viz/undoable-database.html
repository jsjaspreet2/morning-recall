A Draft, Not a Buffer

Drill figma-10-undoable-database: drill 2's mechanism reframed as CRUD on records, and then a batch whose three hardest semantics are answered the other way — the draft starts on its own, undo discards it, and redo dies the moment it opens.

0Part 1 is part 2 with commit() inlined

Both classes have the same three mutators and the same history. The only difference is when the next list becomes a history entry. In part 1 every successful call commits itself. In part 2 the call writes a draft, and commit() is a separate, public step. If your part 1 is shaped like the left panel, part 2 is a rename and one new method.

part 1 — Database
addUser(user) {  this.commit(nextUsers(this.current, 'add', user.id, user))}private commit(next) {  if (next === null) return               // no-op: not a step  this.history = this.history.slice(0, this.index + 1)  this.history.push(next)  this.index++}
part 2 — DraftDatabase
addUser(user) {  this.edit(nextUsers(this.current, 'add', user.id, user))}private edit(next) {  if (next === null) return               // no-op: no draft  if (this.draft === null)                 // the draft STARTS here    this.history = this.history.slice(0, this.index + 1)  this.draft = next}commit() {  if (this.draft === null) return  this.history.push(this.draft)  this.index++  this.draft = null}

The slice that clears redo moved from commit to the first edit. That one move is what makes the rest of the semantics fall out — see section 1.

3Snapshots, priced

This prompt is worded as snapshots — "one committed empty snapshot", "return the draft list, otherwise the committed list" — so the reference uses them. Drill 1 defaulted to inverse commands. Both pass. The graded sentence is the one that says which you chose and what it would cost to switch.

What survives the swap: history, index, undo, redo, commit. What does not: nextUsers becomes three change constructors, and getUsers stops being a lookup. That is the same lesson as drill 1's §06 A, seen from the other side.

5Say it out loud

"This is the layers question with records instead of properties. History is a list of snapshots and an index; undo and redo move the index; a successful call truncates everything above the index and pushes. A call that changes nothing does none of that."
"Part 2 is part 1 with the commit taken out of the mutators. The first edit after a commit starts the draft, and that is where the redo branch is discarded — not at commit — because once you have edited on top of an older state the branch is already unreachable."
"Undo with a draft pending throws the draft away and leaves history alone. That is a different answer from ignoring it, and I'd pick it here because the prompt treats the draft as a dialog the user can cancel. If this were a drag, I'd ignore instead."
"I'm using snapshots because the prompt describes them and the list is small. It's O(n) per step; the day that matters I'd swap the three mutators for inverse commands and keep the history code as it is."

The three rows in section 1 are the whole difference between this and drill 2. Name them before the interviewer does and the batching part is a conversation, not a test.
