The Stack Is The Level

Drill figma-09-rich-text-levels: nine lines of body and the highest ratio of trap to code in the folder. The nine lines are not the rep. Saying why the stack is a stack of containers and not a map of levels is the rep.

All drill visualizations · companion to guide §05 and the drill header

0The problem

Tokens are (level, text) pairs in document order, level a positive integer. Return a nested list where the outer array is the container for level 1, and each deeper level is a list nested inside the one before it.

The invariant that makes the code write itself: stack.length is the level of the container on top. Start with stack = [root] — length 1, holding the container for level 1 — and it stays true by construction. Once it does, "go shallower" and "go deeper" are two while-loops over the same comparison and there is no arithmetic left to get wrong.

1Step through it, one operation at a time

Not one frame per token — one frame per statement, so the two while loops run in front of you. Every container gets a permanent badge (#0, #1, …) the moment it is created, and the same badge appears in the tree and on the stack. When one badge shows up in both places, that is not a copy: it is the same array, and that sharing is the whole reason this algorithm works.

const root: RichNode[] = []const stack: RichNode[][] = [root]        // stack.length === current levelfor (const [level, text] of tokens) {  if (!Number.isInteger(level) || level < 1) throw new Error(...)  while (stack.length > level) stack.pop()              // shallower  while (stack.length < level) {                        // deeper    const parent = stack[stack.length - 1]    const child: RichNode[] = []    parent.push(child)     // link: the tree now holds it    stack.push(child)      // descend: the stack holds the SAME array    stack.push(parent)     // descends into what you just linked INTO    stack.push([])         // descends into an array nothing references  }  stack[stack.length - 1].push(text)}

The frame to watch is stack.push. All three variants grow stack.length by one, so all three terminate and none of them throw. The loop condition cannot tell them apart — stack.length is only half the invariant. The other half is stack[i] is the open container for level i+1, and that half is about identity, which no length check will ever notice.

1bThe stack holds handles into the tree

Two lines store the same reference twice. The tree owns child structurally; the stack holds it as a live handle. So stack[stack.length - 1].push(text) mutates an array that is already inside root — which is why the function can end with a bare return root and no assembly step. The aliasing is the mechanism, not an incidental detail.

That is also why the two near-miss versions fail in different ways, and why one of them is much quieter than the other. Both are run live below against the drill's own part-1 tests.

Notice which two tests every variant passes: empty input, and all tokens at level 1. Those are exactly the cases where the descent loop never runs. If the only tests failing are the ones that go deeper, the bug is inside that loop — that pattern alone localises it before you have read a single line.

The question that separates a load-bearing alias from a hazard, and it is worth asking out loud in the room: if I copied this value instead of sharing it, would the algorithm still work? Here the answer is no — copying child breaks it outright, so the sharing is doing real work and you should say so. In drill 1 the answer is yes — copying the props map costs one new Map and buys a snapshot instead of a view. Same language feature, opposite sign: alias when you are building a structure you will return, copy when you are recording something you will compare against later.

2The trap is the return, not the jump

Everyone handles the deep jump. The bug is keeping a map of "the container for level N" and reusing it on the way back down. Nothing about that looks wrong; it even reads as an optimisation, since it avoids re-walking. Watch it fail on four tokens.

Why the stack cannot have this bug. Going shallower pops the level-2 container off, and nothing holds a reference to it any more. The next descent has no choice but to build a new one. Popping destroys the stale container for free; a cache keeps it alive. Say that sentence when you choose the stack — it is the entire question, and it is the difference between "I used a stack" and "I know what a stack is for here".

3The second trap: how many lists to create

The count is level − stack.length, not level − previousLevel. Those agree on the way down from a token that was at the current depth, and disagree the moment a return has already happened. Letting the stack's length be the level makes both loops conditions you cannot get wrong — there is no subtraction to write at all.

And the text goes only in the innermost new list. Push it into each one as you descend and [(1,"food"), (4,"banana")] comes back as ["food", ["banana", ["banana", ["banana"]]]], which is the kind of output that looks plausible enough to survive a glance.

Part 2The inverse, and where the round trip stops

Level is 1 + how many containers deep you are, so a recursive walk carries it down and there is no state to keep at all.

const walk = (list, level) => {  for (const node of list) {    if (typeof node === 'string') out.push([level, node])    else walk(node, level + 1)  }}walk(nodes, 1)

An empty container emits no tokens, so it cannot come back. Volunteer this rather than claiming a round trip you have not got: "it's an identity in one direction, and in the other only on nestings readRichText could have produced — an empty list has no token representation."

4The answers to the questions they will ask

5Say it out loud

"I'll keep a stack of open containers, and I'm going to maintain that stack.length equals the current level. Then going shallower is popping until the length matches, and going deeper is pushing a new child list per missing level."
"The reason it's a stack and not a map from level to container: when I come back up, popping throws the old level-2 container away. If I cached it, the next descent would append into the list I already closed, and I'd get one shared list where the document has two siblings."
"Levels can skip on the way up. A skip down needs no special case — it's just a shorter walk back — which is why both directions are while-loops rather than an if."
"The contract says levels start at 1 and are positive. I'm throwing on anything else rather than clamping, because clamping hides a producer bug inside output that still looks like a document."

Complexity, in their terms — n tokens, c containers created: time O(n + c), because every container is pushed once and popped at most once, so the inner loops are amortised rather than nested. Auxiliary space O(d) for the deepest level reached; the output itself is O(n + c), which is required, not auxiliary.
